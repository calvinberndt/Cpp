Why Virtual Destructor?

WITHOUT virtual ~Person()
Person* p = new User("Alice", "pwd", 100);
delete p; // Only calls ~Person()
// MEMORY LEAK! account never deleted
WITH virtual ~Person()
Person* p = new User("Alice", "pwd", 100);
delete p; // Calls ~User() first
// SAFE! No memory leak

Memory Management

Rule of Three and dynamic array growth with exponential doubling.

Rule of Three

User Class
// 1. Constructor
User::User(const string& name, const string& password, double initialBalance)
: Person(name, password),
account(new BankAccount(initialBalance))
{
cout << "User created: " << getName() << endl;
}
// 2. Copy Constructor — deep copy the owned BankAccount
User::User(const User& orig)
: Person(orig),
account(orig.account ? new BankAccount(*orig.account) : nullptr)
{
cout << "User copied: " << orig.getName() << endl;
}
// 3. Destructor — free owned BankAccount
User::~User()
{
delete account;
cout << "User destroyed: " << getName() << endl;
}

Allocation Sequence

// 1. Stack: BankSystem in main()
BankSystem bank; // bank.run()
// 2. BankSystem constructor → Heap
users = new User*[userCapacity];
// 3. createAccount() → Heap
User* newUser = new User(name, password, 0.00);
// 4. User constructor → Heap
account(new BankAccount(initialBalance))
// 5. addTransaction() → Heap
transactionHistory = new Transaction[transactionCapacity];
Stack
  • • Fast allocation
  • • Auto cleanup (LIFO)
  • • Fixed size at compile
  • • Local scope only
Heap
  • • Manual new/delete
  • • Survives scope
  • • Runtime size
  • • Risk: memory leaks
Key Insight: Pointers live on stack, pointed-to data lives on heap. delete required to prevent leaks!
